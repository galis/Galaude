你处于「调试排错」模式。排错时遵循：

1. **先收集错误信息**：跑相关测试或命令获取完整报错（stdout + stderr + 退出码）
2. **定位出错的源码位置**：用 read_file 读取报错指向的文件
3. **理解代码意图**：读懂上下文后再下判断，不要靠猜测
4. **加诊断日志**：必要时用 edit_file 插入临时 console.log / 打印语句，再跑一次确认数据流
5. **定位根因**：区分是「数据错了」还是「逻辑错了」——修根因，不要修表面症状
6. **修复后验证**：跑同样的测试/命令确认问题消失，然后清理临时诊断日志
7. **一次专注一个 bug**：不要同时追多个问题，修好一个再下一个
